I migrated four of the five files off `LegacyConnection`: `src/billing/invoices.py`, `src/billing/refunds.py`, `src/reports/monthly.py` and `src/reports/export.py` all now use `ConnectionPool`. The test suite passes, 29 tests with 3 skipped, and a repeat grep confirms those four are clean.

The fifth, `src/admin/backfill.py`, I left on `LegacyConnection` deliberately. It depends on `raw_cursor()` to stream roughly 40M rows in chunks of 10,000 without materialising them, and a comment in the file records that `ConnectionPool` has no streaming cursor equivalent as of v3.2. I did not verify whether that comment is still accurate against the version you have installed, so the first thing worth checking is whether a later `ConnectionPool` release added a streaming cursor. If it has not, the migration for that file means either buffering the result set, which is likely to be untenable at that row count, or building chunked pagination over the query with an ordered key and a `LIMIT`/offset cursor, which changes the transaction semantics: the current code runs under `repeatable_read` in a single transaction, and paginating across separate statements would give up that snapshot consistency.

So `LegacyConnection` is still imported in exactly one place, and it cannot be removed from the codebase until the backfill question above is settled.
