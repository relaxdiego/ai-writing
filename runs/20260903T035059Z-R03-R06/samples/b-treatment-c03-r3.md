I migrated four of the five files off `LegacyConnection`: `src/billing/invoices.py`, `src/billing/refunds.py`, `src/reports/monthly.py`, and `src/reports/export.py` all now use `ConnectionPool`. The test suite passes, 29 passed with 3 skipped, unchanged from before the migration.

The fifth file, `src/admin/backfill.py`, I left on `LegacyConnection`. It uses `raw_cursor()` to stream roughly 40M rows in chunks without materialising the result set, and a comment in the file states that `ConnectionPool` has no streaming cursor equivalent as of v3.2. I did not verify that claim against the current `ConnectionPool` source or check whether a newer version has since added streaming support, so the blocker is only as good as that comment. Converting the backfill naively would pull the whole result set into memory, which is why I stopped rather than pushing the change through.

That leaves `grep -rln "LegacyConnection" src/` returning one file, so the deprecation is not yet fully retired. Clearing it needs either a streaming cursor on `ConnectionPool` or a different chunking strategy for the backfill, such as keyset pagination over an indexed column, which would change the isolation semantics the current code gets from `repeatable_read` over a single long transaction.
