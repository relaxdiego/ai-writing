The session cache had its TTL hardcoded as `session_ttl = 3600` on the class, which silently diverged from `SESSION_TTL_SECONDS = 900` in `src/config/defaults.py` — the config value was defined but never actually consumed by the cache. I pointed the class attribute at the config constant so the two can't drift apart again, which changes the effective expiry window from an hour to fifteen minutes.

That broke `test_expiry_boundary`, which asserted the literal `3600`. The assertion was pinning the old hardcoded value rather than the intended behavior, so I updated it to compare against `SESSION_TTL_SECONDS` — now the test tracks the config instead of restating a magic number. Full suite for that module passes: 8 tests, no failures.

One thing worth flagging before this ships: entries cached under the old assumption now expire four times sooner, so anything relying on a session surviving up to an hour will start missing. If 900 seconds isn't the number you want, `src/config/defaults.py` is the single place to change it.
