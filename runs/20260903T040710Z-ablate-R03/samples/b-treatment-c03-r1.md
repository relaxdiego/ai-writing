Four of the five call sites are migrated: `src/billing/invoices.py`, `src/billing/refunds.py`, `src/reports/monthly.py` and `src/reports/export.py` now go through `ConnectionPool`. The suite passes on those changes (29 passed, 3 skipped).

The fifth, `src/admin/backfill.py`, I left on `LegacyConnection`, so the migration is incomplete. It depends on `LegacyConnection.raw_cursor()` to stream roughly 40M rows in chunks without materialising them, and a comment in the file records that `ConnectionPool` has had no streaming cursor equivalent as of v3.2. Swapping it over naively would pull the whole result set into memory, so the deprecation can't be finished here until either `ConnectionPool` gains a streaming cursor or the backfill is restructured to paginate by key range and issue one bounded query per page. The latter is doable without upstream changes but alters the transaction semantics: the current code holds a single `repeatable_read` transaction across the whole scan, and a paginated version would not, which matters if rows are being written while the backfill runs.
