The session cache had a hardcoded `session_ttl = 3600` that shadowed the `SESSION_TTL_SECONDS = 900` already defined in `src/config/defaults.py`, so the configured value was never actually taking effect. I changed the class attribute in `src/cache/session.py` to reference the config constant, which makes the effective session TTL 900 seconds rather than 3600 — a real behaviour change, since cached sessions now expire four times sooner.

One test, `test_expiry_boundary`, asserted the literal 3600 and failed; I updated it to compare against `SESSION_TTL_SECONDS` so it tracks the config rather than pinning the old value. The full `tests/test_session_cache.py` suite passes, eight tests.

Two things worth flagging. The test failure was the only signal that anything depended on the old value, and I resolved it by following the config, but if 3600 was deliberate for this cache and 900 was meant for something else, the fix should go the other way. Separately, while reading `get()` I noticed `now` is used at line 88 without being assigned anywhere in the function or shown as a parameter; unless it comes from a module-level import I did not see, that line would raise `NameError` on every call. The tests pass, so something must be supplying it, but it is worth a look.
