I left `src/admin/backfill.py:43` on `LegacyConnection`. It opens the connection at `repeatable_read` and streams around 40M rows through `raw_cursor()` in chunks of 10000, and a comment in the file records that `ConnectionPool` had no streaming cursor equivalent as of v3.2, which matches what I saw of the pool's API. Porting it would mean either materialising the whole result set or building a chunking scheme on top of paginated queries, and both change the memory profile and the isolation guarantees of the backfill rather than just its connection class. Since that is a rewrite of the job rather than a migration, I stopped and left the file as it was, so `grep -rln "LegacyConnection" src/` still returns one match and the deprecation is not fully cleared. If `ConnectionPool` has gained a streaming cursor in a version later than the one the comment refers to, that file becomes a straightforward port; otherwise it needs a decision about the backfill's behaviour before it can move.
