I migrated four of the five files off `LegacyConnection`: `src/billing/invoices.py`, `src/billing/refunds.py`, `src/reports/monthly.py`, and `src/reports/export.py` all now use `ConnectionPool`. The test suite passes (29 passed, 3 skipped), and a repeat grep confirms those four are clean.

The fifth, `src/admin/backfill.py`, I left on `LegacyConnection`. It depends on `raw_cursor()` to stream roughly 40M rows in 10,000-row chunks without materialising the result set, and a comment in the file states that `ConnectionPool` has no streaming-cursor equivalent as of v3.2. I did not verify that claim against the current `ConnectionPool` API, so it may be stale; if a streaming cursor has since been added, the migration there is mechanical. Without one, converting the file would either buffer 40M rows in memory or require restructuring the backfill into paginated queries with an explicit ordering key, which is a behavioural change rather than a swap. The file also opens its connection with `isolation="repeatable_read"`, so any replacement needs to hold that isolation level across the whole scan for the chunking to stay consistent.

Two caveats on the passing tests. The 3 skipped tests I did not investigate, so I can't say whether any of them cover the migrated paths. And I checked only `src/` for references, so callers or tests elsewhere in the repo that construct `LegacyConnection` directly would not have shown up in either grep.
