The session cache was carrying its own hardcoded TTL: `session_ttl = 3600` sat as a class attribute on the cache in `src/cache/session.py`, while `src/config/defaults.py` already defined `SESSION_TTL_SECONDS = 900` as the intended value. I replaced the literal with the config constant so the expiry check in `get()` now reads from the single source of truth. The test suite caught the mismatch immediately: `test_expiry_boundary` asserted the literal 3600, so I updated that assertion to reference `SESSION_TTL_SECONDS` as well, and `tests/test_session_cache.py` now passes all eight tests.

Worth being explicit about the consequence, since this is not a pure refactor: sessions previously lived for an hour and now expire after fifteen minutes. Anything relying on the old window — long-running clients that only refresh hourly, or fixtures that assume an entry survives a slow test — will start seeing cache misses. If 3600 was the value you actually wanted in production, the fix belongs in `defaults.py` rather than in the cache class.

Two things I did not verify while making the change. I assumed `SESSION_TTL_SECONDS` was already imported in both files because the tests resolve the name at runtime rather than raising `NameError`, but I did not read the import blocks directly. I also only viewed lines 80–95 of `session.py`, and in that range the `now` used by the expiry comparison is not assigned anywhere, so it comes from earlier in the file or from a scope I did not inspect.
