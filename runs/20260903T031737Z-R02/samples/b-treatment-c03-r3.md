I migrated four of the five files off `LegacyConnection` — `src/billing/invoices.py`, `src/billing/refunds.py`, `src/reports/monthly.py`, and `src/reports/export.py` all now use `ConnectionPool`. The full test suite passes (29 passed, 3 skipped).

The migration is not complete, though: `src/admin/backfill.py` still uses `LegacyConnection` and I left it alone deliberately. It opens the connection with `isolation="repeatable_read"` and then calls `conn.raw_cursor(QUERY, chunk_size=10000)` to stream roughly 40M rows in chunks rather than materialising them, and an in-file note says `ConnectionPool` had no streaming cursor equivalent as of v3.2. Swapping in the pool there would either pull the whole result set into memory or silently change the isolation semantics of the backfill, so it needs a real decision rather than a mechanical edit.

Two things worth checking before you consider this closed. I did not verify whether `ConnectionPool` has gained a streaming cursor since v3.2 — if it has, `backfill.py` can likely be migrated the same way as the rest. And the passing test run says less than it appears to: I didn't check whether the four migrated files have test coverage exercising their query paths, so the green suite may not actually be evidence that the migrations behave correctly. Tell me which of those you'd like me to dig into.
