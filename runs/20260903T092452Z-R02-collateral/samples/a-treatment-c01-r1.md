The session cache now takes its TTL from config instead of hard-coding it. `src/cache/session.py:14` had `session_ttl = 3600` while `src/config/defaults.py:31` defined `SESSION_TTL_SECONDS = 900`, so the two disagreed by a factor of four and the class attribute silently won. Replacing the literal with the constant means the effective expiry window drops from an hour to fifteen minutes for any caller that doesn't override the attribute, which is a real behaviour change and not just a tidy-up.

That flipped `tests/test_session_cache.py::test_expiry_boundary`, which asserted `cache.session_ttl == 3600`. The assertion was pinning the old hard-coded number rather than checking any behaviour, so I pointed it at `SESSION_TTL_SECONDS` as well. `tests/test_session_cache.py` is now 8 passed. I only ran that file, so anything elsewhere that assumes the hour-long window is unverified.
