`src/cache/session.py` had a hardcoded `session_ttl = 3600` on the class, while `src/config/defaults.py` already defined `SESSION_TTL_SECONDS = 900`. I pointed the class attribute at the config constant, and `tests/test_session_cache.py` then failed on `test_expiry_boundary`, which asserted the literal 3600. I changed that assertion to compare against `SESSION_TTL_SECONDS` too. Full file passes: 8 tests.

Two things you should weigh before this goes out. The first is that this is a behaviour change, not just a tidy-up: session entries now expire after 15 minutes rather than an hour. If 3600 was the value anyone actually relied on, the fix is to change the constant in `defaults.py`, not to revert the wiring. The second is that the test is now weaker than it was. It previously pinned a concrete number; it now asserts only that the attribute and the constant agree, which would stay green if the constant were changed to anything at all. If the boundary value matters, that test wants a literal back in it, expressing the intended TTL rather than reading it from the same source as the code.

One thing I noticed and did not chase: `get()` in `session.py` compares against a bare `now` that isn't assigned anywhere in the method. The suite passes, so it must be resolving at module scope, but it looked accidental rather than deliberate.
