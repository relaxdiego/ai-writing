I migrated four of the five files off `LegacyConnection` and left the fifth in place. `src/billing/invoices.py`, `src/billing/refunds.py`, `src/reports/monthly.py` and `src/reports/export.py` now go through `ConnectionPool`. The test suite passes afterwards: 29 passed, 3 skipped. I didn't look into what the three skips are, so I can't tell you whether any of them cover the paths I touched.

`src/admin/backfill.py` still uses `LegacyConnection` and I did not change it. It depends on `raw_cursor()` to stream roughly 40M rows in chunks without materialising them, and a comment in the file records that `ConnectionPool` had no streaming equivalent as of v3.2. Rewriting it against the pool's ordinary cursor would pull the whole result set into memory, so this is a real design gap rather than a mechanical conversion I skipped for convenience. It also opens with `isolation="repeatable_read"`, which the replacement would need to preserve.

So the deprecation isn't fully retired: one call site remains, and `grep -rln "LegacyConnection" src/` still returns that file. If you want it finished, the options are to check whether a later `ConnectionPool` version added a streaming cursor, to write a chunked keyset-pagination loop over the pool that issues one bounded query per chunk, or to leave the backfill on the legacy class with an explicit exemption. The middle option changes the isolation semantics, since each chunk would run in its own transaction, which matters if the source table is being written to during the backfill. Tell me which way you'd like to go and I'll do it.
