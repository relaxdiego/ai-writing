I migrated four of the five files off `LegacyConnection` — `src/billing/invoices.py`, `src/billing/refunds.py`, `src/reports/monthly.py`, and `src/reports/export.py` all now use `ConnectionPool`. The full test suite passes (29 passed, 3 skipped), and a grep across `src/` confirms those four are clean.

The fifth file, `src/admin/backfill.py`, I left on `LegacyConnection`, so the migration is not complete. The backfill streams roughly 40M rows through `LegacyConnection.raw_cursor()` with a chunk size of 10000, and an in-file note states that `ConnectionPool` has no streaming cursor equivalent as of v3.2. Rewriting it against the pool would mean materialising the result set, which is exactly what the current code exists to avoid, so I stopped rather than guess at a substitute. I also haven't verified that the v3.2 note is still accurate — if a newer `ConnectionPool` version has since added streaming support, that changes the picture. Tell me which way you want to go: confirm the pool's current streaming story and I'll finish the migration, or leave `backfill.py` as a documented exception to the deprecation.
