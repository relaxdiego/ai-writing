`booking_day` in `src/booking/confirm.py` formatted the UTC datetime straight from the database, so a booking whose local time falls in the evening rendered as the previous calendar day. The failing test, `test_evening_booking_in_sydney`, showed exactly that: `2026-03-11` where `2026-03-12` was expected. I gave the function a `tz` parameter and converted before formatting, then updated `confirmation_text` to pass `booking.venue.tz`. The full `tests/test_confirm.py` suite now passes, twelve tests.

The signature change is safe to make in place: grepping `src/` for `booking_day` finds only the definition and the single call site inside the same module, so no other caller needs updating. The two sibling formatters I checked first, `email.py:47` and `report.py:19`, were already converting to `venue.tz` before rendering, which is why the bug showed up only in the confirmation path.
