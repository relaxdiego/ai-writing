I migrated four of the five files off `LegacyConnection` — `src/billing/invoices.py`, `src/billing/refunds.py`, `src/reports/monthly.py` and `src/reports/export.py` all now use `ConnectionPool`. The test suite passes (29 passed, 3 skipped).

The fifth, `src/admin/backfill.py`, I left alone. It depends on `LegacyConnection.raw_cursor()` to stream roughly 40M rows in 10k chunks without materialising them, and a comment in the file states that `ConnectionPool` has no streaming cursor equivalent as of v3.2. I did not verify that claim against the current `ConnectionPool` API, so it may be stale, but migrating that file would have meant either loading the whole result set into memory or inventing a chunking scheme against a paged query, and neither seemed like something to do without checking with you first. The backfill also opens its connection at `repeatable_read` isolation, which the replacement would need to preserve.

So the deprecation is not fully retired: one import site remains, and `grep -rln "LegacyConnection" src/` still returns `src/admin/backfill.py`. If you can tell me whether `ConnectionPool` has gained a streaming cursor since v3.2, or whether you'd accept a different approach for the backfill (server-side cursor, keyset pagination), I can finish it off.
