Four of the five files are migrated: `src/billing/invoices.py`, `src/billing/refunds.py`, `src/reports/monthly.py`, and `src/reports/export.py` now go through `ConnectionPool`, and the full test suite passes (29 passed, 3 skipped).

The fifth, `src/admin/backfill.py`, I left on `LegacyConnection`, because migrating it would break the backfill rather than move it. That code opens a `repeatable_read` transaction and streams roughly 40M rows through `LegacyConnection.raw_cursor()` in chunks of 10,000, and a comment in the file records that `ConnectionPool` as of v3.2 has no streaming cursor equivalent. I checked the call and the comment matches what the code does, so the only faithful translation available would have been to materialise the result set, which for a table that size means an out-of-memory failure in production rather than a test failure I could have caught here. Unblocking it needs either a streaming cursor on `ConnectionPool` or a decision to restructure the backfill around keyset pagination, and both of those are changes to the pool's API surface or to the backfill's semantics that go beyond a mechanical migration.

So the deprecation is not yet fully retired: a `grep` for `LegacyConnection` under `src/` still returns that one file, and it will keep returning it until the streaming gap is closed.
