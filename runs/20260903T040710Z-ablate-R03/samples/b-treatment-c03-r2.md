Four of the five call sites are migrated: `src/billing/invoices.py`, `src/billing/refunds.py`, `src/reports/monthly.py`, and `src/reports/export.py` now go through `ConnectionPool`, and the test suite passes at 29 passed, 3 skipped.

The fifth, `src/admin/backfill.py`, I left on `LegacyConnection`, so the migration is not complete. That module streams roughly 40M rows through `LegacyConnection.raw_cursor()` with a chunk size of 10000, under a `repeatable_read` isolation level, and a comment in the file records that `ConnectionPool` has no streaming cursor equivalent as of v3.2. Swapping it to the pool would mean materialising the whole result set, which would blow up memory on any real backfill run, so a mechanical translation was not available to me. I did not verify the comment's claim against the current `ConnectionPool` source; if a streaming API has landed since that note was written, the migration is straightforward, and if not, the backfill needs either a keyset-pagination rewrite or a streaming cursor added to the pool before it can move.
