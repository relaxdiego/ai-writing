Four of the five files are migrated; `src/admin/backfill.py` still uses `LegacyConnection`, and I left it there deliberately.

The four I converted to `ConnectionPool` are `src/billing/invoices.py`, `src/billing/refunds.py`, `src/reports/monthly.py` and `src/reports/export.py`. The full suite passes after the change: 29 passed, 3 skipped. I did not look into what the three skips are or whether they cover any of the migrated paths, so treat that as a green run rather than proof the new code paths are exercised.

The backfill is blocked on a missing capability rather than on effort. It streams roughly 40M rows through `LegacyConnection.raw_cursor()` in 10,000-row chunks, and a comment in the file records that `ConnectionPool` has no streaming cursor equivalent as of v3.2. Swapping in the pool would mean materialising the whole result set, which is the thing the current code exists to avoid. The call also pins `isolation="repeatable_read"`, so any replacement needs to preserve that as well as the streaming. Clearing this one requires either a streaming cursor in a later `ConnectionPool` release or a rewrite of the backfill to page through the query with explicit key ranges, which changes its transactional behaviour and is a larger decision than the migration itself.
