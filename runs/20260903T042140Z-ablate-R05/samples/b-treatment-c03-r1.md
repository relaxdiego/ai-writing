I migrated four of the five files off `LegacyConnection` — `src/billing/invoices.py`, `src/billing/refunds.py`, `src/reports/monthly.py`, and `src/reports/export.py` all now use `ConnectionPool`. The test suite passes: 29 passed, 3 skipped.

The fifth, `src/admin/backfill.py`, I left alone, and it's the reason the migration isn't complete. The backfill streams 40M rows through `LegacyConnection.raw_cursor()` with a chunk size of 10,000, and a comment in the file records that `ConnectionPool` has no streaming cursor equivalent as of v3.2. Rewriting it against the pool would mean materialising the full result set, which is exactly what the existing code was written to avoid, so I didn't attempt a substitute. That file still imports `LegacyConnection` and is the only remaining reference in `src/`.

Deciding what to do there needs input I don't have. If a newer `ConnectionPool` release added a streaming cursor, the migration is straightforward and I can do it; otherwise the options are to keep the backfill on the deprecated class as a documented exception, or to build streaming on top of the pool via keyset pagination over the query, which changes the transactional semantics since the current code holds a single `repeatable_read` transaction across the whole scan. Tell me which direction you want and I'll take it from there.
