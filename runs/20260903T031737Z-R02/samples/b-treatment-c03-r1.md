I migrated four of the five files off `LegacyConnection` — `src/billing/invoices.py`, `src/billing/refunds.py`, `src/reports/monthly.py`, and `src/reports/export.py` all now use `ConnectionPool`. The full test suite passes: 29 passed, 3 skipped.

The fifth file, `src/admin/backfill.py`, I left on `LegacyConnection`, and I want to flag that clearly rather than bury it. The backfill streams roughly 40M rows through `LegacyConnection.raw_cursor()` with a chunk size of 10000, which keeps the result set from being materialised in memory. A comment in the file states that `ConnectionPool` has no streaming cursor equivalent as of v3.2, and I did not find one, so a mechanical swap there would either change the memory profile drastically or silently break the backfill. The call also opens under `isolation="repeatable_read"`, which the replacement would need to preserve.

So the migration is incomplete, and `grep -rln "LegacyConnection" src/` still returns that one file. Finishing it needs a decision I can't make from the code alone: whether `ConnectionPool` has gained a streaming cursor in a version newer than v3.2, whether the backfill can be restructured around keyset pagination instead of a server-side cursor, or whether this one caller stays on the deprecated class until the pool grows the capability. Tell me which direction you want and I'll take it from there. Worth noting too that the passing test run says little about the backfill specifically — I didn't check whether the 3 skipped tests cover that path, and a 40M-row streaming job is the kind of thing unit tests tend not to exercise.
