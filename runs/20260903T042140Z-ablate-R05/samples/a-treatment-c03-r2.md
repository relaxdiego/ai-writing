Four of the five call sites are now on `ConnectionPool`: `src/billing/invoices.py`, `src/billing/refunds.py`, `src/reports/monthly.py`, and `src/reports/export.py`. The test suite passes after the change, 29 passed with 3 skipped, and those 3 were already skipped before I touched anything.

The fifth, `src/admin/backfill.py`, I left on `LegacyConnection`, so the migration is not complete. The backfill streams roughly 40M rows through `LegacyConnection.raw_cursor()` in 10,000-row chunks, and a comment in the file records that `ConnectionPool` had no streaming cursor equivalent as of v3.2. I checked the call and the comment matches what the code does; I did not verify against the current `ConnectionPool` source whether v3.2 is still the shipping version, so it is worth confirming that a streaming API hasn't landed since. Rewriting it against the pooled API without a streaming cursor would mean materialising the full result set, which is the thing the current code exists to avoid, so I did not want to make that call unilaterally.

If `ConnectionPool` has gained a streaming cursor, the fix is small and I can do it now. If it hasn't, the options are to keep an explicit exemption for the backfill until one exists, or to restructure it to page through by keyset rather than stream, which changes its isolation guarantees and deserves a closer look at whether `repeatable_read` was load-bearing there. Tell me which direction you want and I'll finish it.
