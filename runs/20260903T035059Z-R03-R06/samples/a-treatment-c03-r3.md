Four of the five files that referenced `LegacyConnection` now use `ConnectionPool`: `src/billing/invoices.py`, `src/billing/refunds.py`, `src/reports/monthly.py`, and `src/reports/export.py`. The test suite passes after the change, with 29 passing and 3 skipped; I did not investigate the skips, so I can't tell you whether they were already skipped before this work or whether they cover any of the migrated paths.

`src/admin/backfill.py` still uses `LegacyConnection`, and I left it alone deliberately. It opens the connection with `isolation="repeatable_read"` and then iterates `conn.raw_cursor(QUERY, chunk_size=10000)` to stream roughly 40M rows in chunks rather than materialising the result set. A comment in the file states that `ConnectionPool` has no streaming cursor equivalent as of v3.2, and I found nothing in the pool API to contradict it. Rewriting that loop against the pool would either pull the whole result into memory or require reimplementing chunking with keyset pagination over the query, which changes the transactional semantics the `repeatable_read` isolation was presumably chosen to guarantee. Both are larger changes than a mechanical migration, and both need a decision about what the backfill is allowed to cost.

So the deprecation is not fully retired. If the goal is to delete `LegacyConnection` outright, the remaining work is on the pool side: either a streaming cursor in `ConnectionPool`, or an explicit agreement that the backfill can be restructured as a paginated job with weaker isolation.
