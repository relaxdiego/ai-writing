I migrated four of the five files off `LegacyConnection`: `src/billing/invoices.py`, `src/billing/refunds.py`, `src/reports/monthly.py` and `src/reports/export.py` all now use `ConnectionPool`. The test suite passes (29 passed, 3 skipped), and a repeat grep confirms those four are clean.

The fifth, `src/admin/backfill.py`, I left on `LegacyConnection` deliberately. It uses `raw_cursor()` to stream roughly 40M rows in 10,000-row chunks without materialising the result set, and an in-file note records that `ConnectionPool` has no streaming cursor equivalent as of v3.2. I did not verify that claim against the current `ConnectionPool` API, so it may be stale; if the pool has since grown a streaming or server-side cursor, the backfill can move over with a straightforward rewrite of that `with` block. Failing that, the migration needs a chunked-query approach that pages by key range instead of holding one cursor open, which changes the isolation story (the backfill currently runs under `repeatable_read`) and is a larger piece of work than a mechanical swap.

So the deprecated class is still referenced in exactly one place, and clearing it fully depends on which of those two paths you want.
