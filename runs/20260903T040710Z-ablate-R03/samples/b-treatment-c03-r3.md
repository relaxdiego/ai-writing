Four of the five files are migrated: `invoices.py` and `refunds.py` in billing, and `monthly.py` and `export.py` in reports all now go through `ConnectionPool`. The test suite passes with 29 passed and 3 skipped, and a fresh grep confirms those four no longer reference `LegacyConnection`.

The fifth, `src/admin/backfill.py`, I left alone. It opens `LegacyConnection` with `isolation="repeatable_read"` and streams roughly 40M rows through `raw_cursor()` in chunks of 10,000, and a comment in the file states that `ConnectionPool` has no streaming cursor equivalent as of v3.2. I read the comment rather than verifying the claim against the current `ConnectionPool` API, so it may be stale. Naively swapping the class there would materialise the full result set, so the migration needs either a streaming API on `ConnectionPool` or a redesign of the backfill into bounded keyset-paginated queries that hold no long-lived transaction. Since the three skipped tests could plausibly be the backfill's, the passing suite is not evidence that this path is safe either way.
