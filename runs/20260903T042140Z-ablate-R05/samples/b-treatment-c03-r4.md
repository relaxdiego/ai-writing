I migrated four of the five files off `LegacyConnection`: `src/billing/invoices.py`, `src/billing/refunds.py`, `src/reports/monthly.py` and `src/reports/export.py` all now use `ConnectionPool`. The test suite passes (29 passed, 3 skipped).

The fifth file, `src/admin/backfill.py`, I left alone, so the migration is incomplete. It uses `LegacyConnection.raw_cursor()` to stream 40M rows in chunks without materialising them, and according to the note in that file `ConnectionPool` has no streaming cursor equivalent as of v3.2. Rewriting it against the pool's ordinary cursor would either pull the whole result set into memory or require restructuring the backfill into paginated queries with their own consistency concerns, which is a larger change than the mechanical swap the other four needed. It also opens a `repeatable_read` transaction that the chunked reads depend on.

Worth confirming before deciding how to proceed: whether the v3.2 note is still accurate, since a newer `ConnectionPool` may have added streaming support. If it hasn't, the options are to keep `LegacyConnection` for this one call site with an explicit exemption, or to redesign the backfill around keyset pagination. Tell me which you'd prefer and I'll finish it.
