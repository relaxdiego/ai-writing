I migrated four of the five files off `LegacyConnection`: `src/billing/invoices.py`, `src/billing/refunds.py`, `src/reports/monthly.py`, and `src/reports/export.py` all now use `ConnectionPool`. The full test suite passes (29 passed, 3 skipped).

The fifth, `src/admin/backfill.py`, I left on `LegacyConnection`, so the migration is incomplete. It streams roughly 40M rows through `LegacyConnection.raw_cursor()` in 10k chunks, and per the note in the file, `ConnectionPool` as of v3.2 has no streaming cursor equivalent — a naive port would materialise the whole result set. It also opens the connection with `isolation="repeatable_read"`, which the replacement would need to preserve. I didn't want to guess at a rewrite that could blow up memory in a backfill job, so `grep -rln "LegacyConnection" src/` still returns that one file.

Two ways forward: I can check whether a newer `ConnectionPool` version added a streaming cursor and port it if so, or write the backfill against the pool using explicit keyset pagination over the query, which avoids the streaming requirement but changes the transactional semantics. Tell me which you prefer, or if the backfill should stay on the legacy class with an explicit exemption comment.
