Four of the five files that referenced `LegacyConnection` now use `ConnectionPool`: `src/billing/invoices.py`, `src/billing/refunds.py`, `src/reports/monthly.py` and `src/reports/export.py`. The full test suite passes after the change, 29 passed with 3 skipped, though I did not check what those skipped tests cover, so I can't tell you whether any of them exercise the paths I touched.

The fifth file, `src/admin/backfill.py`, I left on `LegacyConnection`. It depends on `raw_cursor()` to stream roughly 40M rows in chunks without materialising them, and a comment in the file states that `ConnectionPool` has no streaming-cursor equivalent as of v3.2. I did not verify that claim against the current `ConnectionPool` source, so it may be stale; if a streaming cursor has landed since, the migration there is mechanical. If it hasn't, the backfill needs either a rewrite around keyset pagination or a new streaming API on the pool, and that is a design decision about memory and transaction semantics rather than a find-and-replace. The `isolation="repeatable_read"` setting is part of the same question, since a paginated rewrite would need an equivalent guarantee to avoid skipping or double-counting rows mid-backfill.

The practical consequence is that `LegacyConnection` cannot be deleted yet, and the deprecation is incomplete until the backfill question is settled.
