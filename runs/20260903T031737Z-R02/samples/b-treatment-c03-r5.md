I migrated four of the five files off `LegacyConnection`: `src/billing/invoices.py`, `src/billing/refunds.py`, `src/reports/monthly.py`, and `src/reports/export.py` all now use `ConnectionPool`. The test suite passes — 29 passed, 3 skipped.

The fifth file, `src/admin/backfill.py`, I left on `LegacyConnection`, and I want to flag it rather than bury it. The backfill streams roughly 40M rows through `LegacyConnection.raw_cursor()` with a chunk size of 10,000, and a comment in the file states that `ConnectionPool` has no streaming-cursor equivalent as of v3.2. Migrating it naively would mean materialising the whole result set, so I stopped rather than swap in something that would pass tests and then fall over on production data volumes. I did not verify that claim against the current `ConnectionPool` API myself — the comment may predate a newer version, so it is worth checking whether a streaming path has since been added.

That leaves the deprecation incomplete. Your options are to keep the one remaining call site and suppress the deprecation warning there until `ConnectionPool` grows a streaming cursor, or to rework the backfill around keyset pagination so it can page through the table with pooled connections instead of holding one long-lived cursor. The second is a real change in transaction semantics — the current code runs under `repeatable_read` for the whole scan — so it needs a decision about whether the backfill can tolerate seeing concurrent writes mid-run.
