The session cache had its TTL hardcoded as `session_ttl = 3600` in `src/cache/session.py`, while `src/config/defaults.py` defined `SESSION_TTL_SECONDS = 900` as the intended value. I changed the class attribute to reference the config constant so the two no longer disagree, which means expiry in `get()` now uses the 15-minute window rather than an hour.

That change broke `test_expiry_boundary`, which asserted the literal `3600`. Since the test was pinning the stale hardcoded value rather than any real behaviour, I updated the assertion to compare against `SESSION_TTL_SECONDS`; the full file now passes at 8 tests.

Two things worth flagging. I did not verify that `SESSION_TTL_SECONDS` is imported in either file, so if the import is missing you will get a `NameError` at class-definition time on the next import of the module. Worth a quick check before committing. More importantly, this is a real behaviour change and not just a cleanup: sessions that previously survived an hour will now expire after fifteen minutes. If anything downstream was relying on the longer window, the config value may be the thing that is wrong rather than the hardcoded one, and I would want your read on which of the two numbers reflects the intent.
